2. We Have Features, So How Do We Get a Prediction?

Take one employee from the table: Experience = 5, Education = Master, Job Role = Engineer, Location = Bangalore.

Based on these features, the model needs to produce a salary. But how does it decide what number to produce?

The model needs some way to decide how much each feature contributes to the final prediction.

3. What Is a Weight?

Do you think all these features should have exactly the same influence on salary?

Clearly not. This is where weights come in. A weight is a number that decides how strongly a feature affects the prediction.

Experience ──→ w₁ ──┐ Education ───→ w₂ ──┤ Job Role ────→ w₃ ──┼──→ Prediction Location ────→ w₄ ──┘
If the weight is…MeaningSalary example
Large positiveFeature pushes the prediction up stronglyEach extra year of experience adds a lot
SmallFeature barely mattersSomething unrelated, like an employee ID
NegativeFeature pushes the prediction downe.g. number of months away from work
Learned parameterThe model doesn't know in advance which feature is important. During training, it learns the weight values from the data. That learning is what this whole session is about.

4. But Is a Weight Enough?

Suppose Experience = 5 and its weight = 2. The contribution is 5 × 2 = 10. Now think about a fresher: Experience = 0. Contribution = 0 × 2 = 0.

Does a fresher with 0 years of experience earn a salary of 0? What's missing?

No: there is always a starting salary. The features × weights alone can't produce it. So we add one more number, the bias: a constant that is added to every prediction. It's the prediction when all features are 0.

ŷ = wx + bw → weight · x → feature · b → bias (intercept) · ŷ → prediction
Weight wBias b
JobControls the slope: how much ŷ changes per unit of xControls the starting point: moves the whole line up or down
Depends on x?Yes: its effect is w × xNo: same constant for every record
When x = 0Contributes nothingŷ = b
Salary exampleExtra salary per year of experienceStarting salary for a fresher

You may remember y = mx + c from school: m is our weight, c is our bias.

9. What Is Loss?

Loss is a single number that measures how wrong the model is. For regression, we square the error:

Loss L = (ŷ − y)²Chitra: (50 − 60)² = (−10)² = 100
StudentErrorSquared error
Farah−10100

Why square? Reason 1Squares are never negative, so errors can't cancel each other out.
Why square? Reason 2Big mistakes are punished more: an error of 2 costs 4, an error of 10 costs 100.

Smaller loss → the prediction is closer. Larger loss → further away. Our goal: make the loss as small as possible.

Part 3 Learning: gradient, learning rate, update

10. The Model Needs a Direction: the Gradient

Imagine standing on a hillside in thick fog. Your goal is the lowest point, but you can't see it. All you can do is feel the slope under your feet and ask: "From where I'm standing, which way is downhill?"

Hill pictureIn the model
Where you are standingThe current weight (w = 8)
Your heightThe loss (100)
The slope under your feetThe gradient
The bottom of the valleyThe best weight (w = 10, loss 0)

How is the gradient calculated?

The gradient is calculated from the loss, with respect to the weight. It answers one question:

Gradient = how much the loss changes when the weight changes a littleWritten ∂L/∂w and read as "the derivative of the loss with respect to the weight"

We can see it with a simple experiment on Chitra's record: nudge the weight a tiny bit and watch the loss.

TryWeight wPrediction 5w + 10ErrorLoss
Now8.0050.00−10.00100.0000
Nudge w up by 0.018.0150.05−9.9599.0025
Change in loss for a 0.01 change in weight−0.9975
Gradient ≈ change in loss ÷ change in weight = −0.9975 ÷ 0.01 ≈ −100

So at w = 8, the gradient is about −100: increasing the weight makes the loss go down, quite steeply.

How to read the gradient

Gradient is…MeaningSo we…
NegativeIncreasing w lowers the lossIncrease the weight
PositiveIncreasing w raises the lossDecrease the weight
Close to 0Flat ground: we're at (or near) the bottomStop: this is the best weight
Large (either sign)Steep: far from the bottomExpect a bigger correction
The gradient is not the new weight−100 doesn't mean the weight becomes −100. It is the slope at w = 8. It tells us which direction to move and how steep the hill is.

Optional: how the gradient is calculated exactly (for anyone who wants the maths, not needed to follow the course)

The nudge experiment gives an approximate gradient. Calculus gives the exact value instantly, using the chain rule.

Why a chain?

The loss L = (ŷ − y)² doesn't contain w directly. The weight affects the loss only through the prediction:

w ──changes──▶ ŷ ──changes──▶ L
∂L/∂w = ∂L/∂ŷ × ∂ŷ/∂w(how the loss reacts to the prediction) × (how the prediction reacts to the weight)

Note: it's ŷ (the prediction), not y (the actual value). y comes from the data and never changes when w changes.

Link 1: how the loss reacts to the prediction

L = (ŷ − y)² Rule: the derivative of (something)² is 2 × (something) ∂L/∂ŷ = 2(ŷ − y) = 2(50 − 60) = −20

Link 2: how the prediction reacts to the weight

ŷ = wx + b ∂ŷ/∂w = x × (∂w/∂w) + 0 ← b is a constant, so it disappears = x × 1 = x = 5

Join the links

∂L/∂w = ∂L/∂ŷ × ∂ŷ/∂w = 2(ŷ − y) × x = (−20) × 5 = −100 ✓ matches the nudge experiment
The formula for our modelGradient = 2 × error × x. In words: "how wrong we were" × "how much this weight was involved". If x were 0, the weight played no part in the prediction, so its gradient would be 0. Libraries like PyTorch do this calculation automatically for millions of weights.
Takeaway: The gradient is calculated from the loss with respect to the weight: how much the loss changes when the weight changes a little. Negative → increase w. Positive → decrease w. Near 0 → stop.

11. But How Big Should the Step Be?

Suppose you know which direction is downhill. Should you take a tiny step or a huge jump?

The gradient is only the slope right where you're standing. If you jump too far, you can land on the other side of the valley, even higher than before.

So we multiply the gradient by a small number called the learning rate (η, "eta"). It controls how big each step is.

Learning rateEffectHill picture
Too smallRight direction, but very slowBaby steps downhill
GoodReaches the bottom in a few stepsSteady, confident steps
Too bigOvershoots; can make the loss explodeLeaping over the valley onto the other hill
Who chooses it?The learning rate is a hyperparameter: we choose it before training (the model doesn't learn it). Teams usually try a few values and keep the one with the best validation loss.

12. Updating the Weight

New weight = Old weight − (Learning rate × Gradient)w_new = w_old − η × ∂L/∂w
Current weight = 8 Gradient = −100 Learning rate = 0.01 New weight = 8 − (0.01 × −100) = 8 − (−1) = 8 + 1 = 9
Why is there a minus sign in the rule?

The gradient points uphill (the direction that makes the loss bigger). We want to go downhill, so we move the opposite way:

Gradient− η × gradientWeight goes…
Negative (−100)− 0.01 × (−100) = +1Up ✓
Positive (e.g. +100)− 0.01 × (+100) = −1Down ✓

Nobody picked 9 by hand: the rule produced it from the current weight, the gradient and the learning rate.

13. Did the Update Actually Help?

BEFORE
Weight = 8 Prediction = 8 × 5 + 10 = 50 Loss = (50 − 60)² = 100
AFTER ONE UPDATE
Weight = 9 Prediction = 9 × 5 + 10 = 55 Loss = (55 − 60)² = 25
Did the model improve?

Yes! The loss dropped from 100 to 25. The prediction moved from 50 to 55, closer to the actual 60.

14. Repeat the Process

One update is not enough. After each update, the model makes a new prediction, calculates a new loss and a new gradient at the new weight, then updates again.

Notice • The loss falls every step: 100 → 25 → 6.25 → 1.56 → 0.39.
• The gradient shrinks towards 0 as we approach the bottom, so the steps get smaller by themselves (+1, +0.5, +0.25…). Nobody told the model to slow down.
• The weight approaches 10, the bottom of the valley.
Prediction → Loss → Gradient → Update → Repeat

Repeatedly updating the weights in the direction that reduces the loss is called gradient descent.

Part 4 From one record to a real dataset

15. What About a Real Dataset? Mean Squared Error (MSE)

So far we learned from one student. A real dataset has thousands of records. One weight has to work well for all of them.

With 5 students, we have 5 losses. How do we turn them into one number?

We take the average of the squared errors. That is the Mean Squared Error (MSE):

MSE = (1/N) × Σ (ŷᵢ − yᵢ)²N = number of records · Σ = add up for every record · i = the record number

In words: square each record's error, add them all up, divide by the number of records.

Step 1: loss for the whole dataset (w = 8, b = 10)

Exactly the same idea as before: each record gives its own gradient (2 × error × x, from the optional box in section 10), and we take the average.

Takeaway: With many records: calculate each record's error and gradient, then average. The update rule doesn't change.

Each weight gets its own gradient, calculated the same way but using its own feature:

The patternEvery weight is updated at the same time, each with its own gradient. With 100 features there are 100 weights and 100 gradients per step. The list of all of them together is what people call "the gradient".

17. How Many Records Do We Use Before Updating?

If we have 10,000 records, do we have to process all 10,000 before updating the weight even once?

No. We can choose. First, three words:

IterationOne gradient calculation + one weight update10 ÷ 4 → 3 iterations (4 + 4 + 2)
EpochOne complete pass through all the training recordsAfter 3 iterations, every record has been used once

Look at this dataset. Some columns are useful; some are just noise that has nothing to do with marks:

Roll number and bench row have nothing to do with marks, but with few records the model may still find accidental patterns in them.

With 100 features and limited data, the model might give large weights to useless columns like roll number. Can we encourage it to keep weights under control?

Yes, with regularisation: we add a penalty for large weights to the loss. Now a weight must "earn its place" by really reducing the error.

Total loss = MSE + λ × (size of the weights)λ ("lambda") = how strong the penalty is: a hyperparameter we choose
L1 (Lasso)L2 (Ridge)
Penalty|w₁| + |w₂| + … (absolute values)w₁² + w₂² + … (squares)
EffectPushes useless weights to exactly 0: the feature is droppedShrinks all weights a little; rarely exactly 0
AnalogyDeclutter: throw unused items awayPack lighter: a bit less of everything

19. What Changes for Classification?

So far we predicted a number (marks). What if the target is a category, like Spam vs. Not spam?
Emails
EmailNumber of linksContains "free"?Sender known?Actual
#17YesNoSpam
#20NoYesNot spam
#32NoNoSpam
#45YesYesNot spam

Three things change. Everything else (gradient, learning rate, update, epochs) stays the same.

Change 1: the output becomes a probability

The model still calculates a raw score z = wx + b. A function called sigmoid squashes it into a probability between 0 and 1. Then a threshold (usually 0.5) turns it into a decision.

features → z = wx + b → sigmoid → probability p → p ≥ 0.5 ? → Spam / Not spam

Change 2: the loss becomes cross-entropy

Instead of squaring the error, we look at the probability the model gave to the correct answer. High → small loss. Confidently wrong → very big loss.

Loss = −log(probability given to the correct answer)
EmailActualModel's P(spam)P(correct answer)LossVerdict
#1Spam0.900.900.11Confident and right: tiny loss
#2Not spam0.200.800.22Right: small loss
#3Spam0.300.301.20Wrong: bigger loss
#4Not spam0.950.053.00Confidently wrong: very big loss

Natural log, rounded. The average of this column is the dataset's loss, exactly like MSE was an average.

Change 3: how we judge success

Instead of "how many marks off", we ask "how often is it right, and does it catch the important cases?" (accuracy, precision, recall: a later session).

ProblemOutputLoss
Regression (marks, salary)A numberMSE
Binary classification (spam / not)One probability (sigmoid)Binary cross-entropy
Multiclass (cat / dog / bird)A probability per class, adding to 100% (softmax)Categorical cross-entropy
