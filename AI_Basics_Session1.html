Why datasets matter

  • They are the only teacher. The model knows nothing except what the data shows it.
  • They set the limits. A model trained only on Bengaluru houses can't price houses in Delhi.
  • They pass on mistakes. Wrong or biased data produces a wrong or biased model: garbage in, garbage out.
  • They test the model. Part of the data is kept aside to check whether the model really learned (section 9).

    6. Supervised learning: regression vs. classification

    In supervised learning, every example has an answer (label). What kind of answer it is decides the type of problem.

    📈 Regression: "How much? How many?"

    The answer is a number on a scale. Being "close" matters: predicting ₹74 L when the truth is ₹75 L is a good guess.

    Examples: house price, delivery time, tomorrow's temperature, number of tickets tomorrow.

    🏷️ Classification: "Which one? Which group?"

    The answer is a category (a name or tag). There's no "close": an email is either spam or not spam.

    Examples: spam / not spam, which team gets this ticket, which digit is in an image.

    The 2-second testAsk: "Can I take an average of the answers, and does 'close' make sense?"
    ✅ Yes → regression. ❌ No (you can't average "Billing" and "Login") → classification.

    Continuous vs. discrete: clearing up a common confusion

    Kind of answerWhat it meansExamplesUsually solved with
    Continuous numberAny value, including decimals₹74.6 L, 27.3°C, 18.5 minutesRegression
    Discrete countWhole numbers only, but still an amountTickets tomorrow: 0, 1, 2, … 140Regression (count regression)
    Discrete categoryA fixed set of names or groupsSpam / not spam; Billing / Login / BugClassification
    ⚠️ Trap: numbers that are really categoriesA PIN code, an employee ID or a product code look like numbers but are really names, so predicting them is classification. In-between case: a 1–5 star rating is ordered, so it can be treated either way.

    Types of regression (concept level)

    TypePlain meaningExample
    SimpleOne input predicts the numberHouse size → price
    MultipleMany inputs together predict the numberSize + location + age → price
    LinearRoughly a straight lineEvery extra 100 sq ft adds about the same amount
    Non-linearThe relationship curves or flattens outCrop yield rises with fertiliser, then flattens, then drops
    CountWhole-number counts that can't go below zeroPatient visits to a clinic tomorrow

    Types of classification

    TypePlain meaningExample
    BinaryExactly 2 possible answersSpam / not spam · repay / default
    Multiclass3 or more answers; pick exactly oneTicket → Billing, Technical, Account or Other
    Multi-labelSeveral answers can be true at onceA movie tagged Action + Comedy
    AnalogyBinary = a light switch. Multiclass = a TV remote (exactly one channel). Multi-label = pizza toppings (as many as apply).

    How do we judge success? (plain words)

    RegressionClassification
    Main question"On average, how far off are we?""How often are we right, and do we catch the important cases?"
    Example"Our price predictions are off by about ₹4 L on average.""We catch 90 of every 100 frauds; 5 of every 100 alerts are false alarms."

    7. Unsupervised learning: when there are no labels

    So far every dataset had an answer column (y). But very often we have only the features (X) and no answers at all. Can a machine still learn something? Yes. It can discover structure by itself: which rows are similar, which rows are strange.

    Analogy: sorting a mixed box of LEGONobody gives you instructions or names for the pieces. You still naturally put similar pieces together: by colour, by size, by shape. You found the groups yourself. That is unsupervised learning.

    Same data, two situations

    Try it: watch the machine find customer groups (clustering)

    👆 90 shoppers, with only two features: visits per month and average spend per visit. No labels. Choose how many groups to look for, then press Step repeatedly or Run.
    How the machine does it (one popular method) 1. Drop a few centre markers (the stars), spread across the data.
    2. Every customer joins the nearest centre.
    3. Each centre moves to the middle of its group.
    4. Repeat 2–3 until nothing changes.
    The machine finds groups; humans give them meaning With 3 groups, the machine finds something like this, but it only knows "group 1, 2, 3". We look at each group and name it:
    • Occasional big spenders: few visits, high spend per visit.
    • Loyal regulars: many visits, small baskets.
    • Casual browsers: few visits, small spend.
    The marketing team can now send a different offer to each group, without anyone ever labelling a customer.

    What clusters can look like

    Real groups aren't always neat circles. Different methods are good at different shapes, and some methods can also say "this point doesn't belong to any group" (noise).

    What unsupervised learning is used for

    TaskWhat the machine doesReal examples
    ClusteringPuts similar rows into groups nobody defined in advanceCustomer segments · grouping similar news articles · grouping support tickets by topic · grouping patients with similar symptoms
    Anomaly detectionLearns what "normal" looks like and flags rows that don't fitUnusual card transactions · a machine sensor behaving strangely · odd login activity
    AssociationFinds things that often happen together"People who buy bread often buy butter" · "frequently bought together" on shopping sites
    Simplifying data (dimensionality reduction)Squeezes many columns into a few, keeping the important informationTurning 100 survey questions into 3 main themes · making data easier to plot

    Supervised vs. unsupervised at a glance

    SupervisedUnsupervised
    DataX and y (features + answers)Only X (features)
    GoalPredict the answer for new rowsDiscover groups, patterns or odd rows
    How we check itCompare predictions with the real answersNo answers to compare with: we check that groups are tight and well separated, and that they make sense to people who know the business
    Example"Is this transaction fraud?" (using past fraud labels)"Which transactions look unusual?" (no labels)
    ⚠️ Watch outThe machine will always find the number of groups you ask for, even if the data has no real groups. Ask for 5 groups in the demo above and it happily makes 5. Choosing the number of groups, and checking the groups mean something, is our job.
    Takeaway: No labels? The machine can still learn the shape of the data: which rows are similar (clustering), which rows are strange (anomaly detection), and what goes together. Humans then give the groups meaning.

    8. Sampling: choosing which rows to use (and the random seed)

    Sampling means picking a smaller group (a sample) from a bigger group (the population). It's the first step to splitting data fairly.

    AnalogyA cook tastes one spoon of soup to judge the whole pot. That only works if the soup is stirred well. A bad sample (only the top layer) gives the wrong answer.

    Where sampling shows up in ML

    WhenWhat we sample
    Collecting dataWe can't survey every customer in India, so we survey a sample.
    Splitting dataTrain / validation / test sets are samples of the full dataset (next section).
    TrainingEvery mini-batch is a small random sample of the training rows (Session 2).
    Fixing imbalanceWe over-sample the rare class or under-sample the common one.

    Try it: random vs. stratified sampling

    👆 200 customers, 10% are fraud (red). Draw a sample of 20 and count the red ones.
    Pick a method. The ideal sample of 20 has exactly 2 red (10%).

    Click "Simple random" several times: every click gives a different sample. Now tick the seed box and click again: the same sample every time. Change the seed number and you get a different, but again repeatable, sample.

    Types of sampling

    TypeHow it worksExampleGood / watch out
    Simple randomEvery row has an equal chancePick 1,000 random customers✅ Fair and simple. ⚠️ Can miss rare groups by bad luck.
    StratifiedSplit into groups first, then sample each group in the right proportionKeep 10% fraud in train and test✅ Best for imbalanced data and train/test splits.
    SystematicPick every k-th rowEvery 10th invoice✅ Easy. ⚠️ Breaks if the data has a repeating pattern.
    ClusterPick whole groups, then use all rows in themPick 5 cities, survey everyone there✅ Cheap. ⚠️ Chosen groups may not represent the rest.
    ConvenienceTake whatever is easiestSurvey only your office colleagues⚠️ Usually biased. Avoid for real models.
    Over-samplingRepeat (or create similar) rows of the rare classCopy fraud rows so the model sees more✅ Helps imbalance. ⚠️ Training data only.
    Under-samplingDrop some rows of the common classKeep 10% of normal transactions✅ Balanced, faster. ⚠️ Throws information away.
    With or without replacementWithout replacement: once a row is picked, it can't be picked again (normal splitting). With replacement: a row can be picked more than once (bootstrapping, used later by random forests).

    The random seed (random state): making "random" repeatable

    Computers don't produce truly random numbers. They follow a long, fixed recipe that only looks random. The seed is the starting point of that recipe. Same seed → the same "random" sequence → the same sample, the same split, every time.

    Analogy: shuffling cards with a recorded shuffleIf you write down exactly how you shuffled a deck, a friend can repeat the shuffle and get the identical order. The seed is that written-down shuffle.
    Why it mattersExample
    ReproducibilityYou and a colleague both split the data with seed 42 → you get exactly the same training and test rows, so your results match.
    Fair comparisonsComparing two models? Use the same seed so both see the same split. Otherwise one may just have got an easier test set.
    DebuggingIf a result looks strange, you can re-run and get the same thing, instead of a different result each time.

    In tools you'll see it as random_state or seed (for example, when splitting data into train and test). The number itself doesn't matter (42 is just a popular joke choice); what matters is using the same one.

    ⚠️ Don't "shop" for a lucky seedTrying many seeds and keeping the one with the best test score is cheating yourself: the good score was luck, not a better model.
    Golden ruleSplit into train / validation / test first. Only then over- or under-sample, and only the training set. Otherwise copies of a row can end up in both train and test (data leakage).
    Takeaway: A good sample looks like the population in miniature. Use stratified sampling when a class is rare, and a fixed seed / random_state so anyone can reproduce your exact sample.

    9. Train, validation and test: in depth

    Why we split the data, why roughly 80% goes to training, and what each part is really for.

    The school analogy 📘 Training set = textbook and class notes. The student learns from these.
    📝 Validation set = practice / mock tests. The teacher checks what's working and adjusts.
    🎓 Test set = the final board exam. Taken once, at the end, with unseen questions. The honest score.

    Why split at all?

    If we test a model on the examples it learned from, it can score 100% just by memorising, like a student who memorised the answer key. We only know it truly learned by checking on examples it has never seen.

    Why about 80% for training?

    More data for training →the model learns patterns better. But less is left to check it, so the score is less trustworthy.
    More data for checking →a more reliable score. But the model learned from fewer examples.

    80/10/10 or 70/15/15 is a common starting point: most data to learn from, enough kept aside for a fair check. It's a habit, not a rule:

    Dataset sizeTypical split (train / val / test)Why
    Small (hundreds to a few thousand)60 / 20 / 20, or cross-validationCheck sets need a bigger share to have enough examples.
    Medium (tens of thousands)70 / 15 / 15 or 80 / 10 / 10The classic balance.
    Huge (millions)98 / 1 / 11% of 10 million is still 100,000 rows: plenty to check with.

    Try it: split calculator

    💡 The split is random, so it uses a seed / random_state (section 8) to make it repeatable. For rare classes, make it a stratified split.

    What exactly is the validation set for?

    • Which model? Compare a simple and a complex model; keep whichever does better on validation.
    • Which settings? Settings we choose before training (how complex the model is, how long to train) are called hyperparameters. Try a few and keep the best on validation.
    • When to stop training? Watch the validation score and stop when it stops improving (section 10).
    ⚠️ Common myth: "Validation is only for deep learning"Not true. Validation is used in classic machine learning too. The difference is how:
    WhereHow validation is used
    Classic MLTo compare models and pick settings. With small data, often cross-validation: split training data into 5 parts, train on 4, check on the 5th, rotate 5 times and average.
    Deep learningChecked after every full pass through the training data (an epoch, explained in Session 2). Training stops when validation stops improving: early stopping.
    Fine-tuning an LLMSame idea: a held-out validation set is checked during fine-tuning so the model doesn't just memorise the small dataset.
    ⚠️ Common myth: "The validation set prevents overfitting"It detects overfitting, like a smoke alarm. We then act on it (section 10).

    The test set: why only once, at the very end?

    If we keep checking the test score and tweaking the model, we slowly tune the model to the test set. The final score becomes too optimistic, and the model does worse in the real world.

    AnalogyA teacher who sees the board-exam questions and keeps adjusting lessons to match them: marks go up, real understanding doesn't.

    The full workflow

    Step 1Split the data first (with a seed)
    Step 2Train on the training set
    Step 3Check on the validation set
    Step 4Adjust the model or settings; repeat 2–3
    Step 5Pick the best model using validation
    Step 6Check once on the test set. Report it.

    Splitting mistakes to avoid

    MistakeWhy it's a problemDo this instead
    Shuffling time-based dataThe model "sees the future" during trainingTrain on the past, validate on later data, test on the most recent
    Same person in train and testThe model recognises the patient, not the diseaseSplit by person / patient / customer, not by row
    Duplicates across splitsThe test set secretly contains training rowsRemove duplicates before splitting
    Rare class missing from a splitWith 1% fraud, a random split may put almost none in testUse a stratified split
    Cleaning using the whole datasetTest-set information leaks into trainingSplit first, then decide cleaning steps on training data only
    No seedEvery run gives a different split, so results can't be reproducedFix the random_state
    Takeaway: Train to learn, validate to choose and tune (in classic ML and deep learning), test once for the honest score.

    10. Did the model really learn? Underfitting, overfitting, bias and variance

    The goal is not a perfect score on the training data. The goal is a model that does well on new data it has never seen. This is called generalisation.

    Three students preparing for an exam 🙁 Student A barely studied: does badly on practice papers and the real exam. → Underfitting
    🤓 Student B memorised every past paper word for word: 100% on past papers, but fails when the exam asks the same idea in a new way. → Overfitting
    😊 Student C understood the concepts: does well on past papers and the new exam. → Good fit (generalises)

    How to diagnose it: compare training and test scores

    Example: a classification model, scored by accuracy (% of correct answers).

    CaseTraining accuracyTest accuracyGapDiagnosis
    A62%60%Small, but both low🟡 Underfitting (high bias): hasn't learned the pattern even on data it has seen
    B99%71%Big gap🔴 Overfitting (high variance): learned the training data "too well", including its noise, so it doesn't work on new data
    C91%89%Small, both high✅ Good fit: learned the real pattern and generalises
    D100%100%None🚩 Suspicious! Too good to be true. Check for data leakage (a test row or the answer hidden in the features).
    Rule of thumb Both scores low → underfitting.   Training high, test much lower → overfitting.   Both high and close → good fit.
    (During building, compare training with validation; the test set is saved for the final check.)

    Bias and variance: the two kinds of mistakes

    Plain meaningShows up asGoes with
    BiasThe model's assumptions are too simple, so it misses the real pattern in the same way every time. (Example: drawing a straight line through data that clearly curves.)Low training score and low test scoreUnderfitting
    VarianceThe model is too sensitive to the exact training rows. Change the training data a little and the model changes a lot, because it learned the noise.High training score, much lower test scoreOverfitting

    The trade-offMaking a model more complex lowers bias (it can follow the pattern better) but raises variance (it starts following the noise too). Making it simpler does the opposite. We look for the middle: complex enough to catch the pattern, simple enough to ignore the noise.

    Why it happens, and what to do

    Common reasonsWhat to try
    Underfitting
    (high bias)    		 • Model too simple for the pattern (a straight line for a curve)
    • Features don't carry enough information (predicting house price from paint colour only)
    • Not trained long enough
    • Too much regularisation (Session 2)    		 • Use a more flexible model
    • Add better or more informative features
    • Train longer
    • Reduce regularisation
    Overfitting
    (high variance)    		 • Model too complex for the amount of data
    • Too little training data
    • Noisy data or wrong labels (the model memorises the mistakes)
    • Trained for too long
    • Too many irrelevant features (ID numbers, house number…)    		 • Get more (and cleaner) training data
    • Use a simpler model
    • Add regularisation (L1 / L2, Session 2)
    • Early stopping, using the validation set
    • Remove irrelevant features
    • Use cross-validation to check the result is stable

    What a good model looks like

    A generalised model ✅ Good score on data it has never seen (validation and test)
    ✅ Training and test scores are close to each other (small gap)
    ✅ Learned the real pattern, not the noise or quirks of the training rows
    ✅ Its result stays similar with a different split or seed
    Why we don't chase 100% accuracy • Real data has noise. Labels contain mistakes, and some things are simply unpredictable (two identical-looking loan applicants can behave differently). No model can be right about pure chance.
    • 100% on training data usually means memorising, which is exactly overfitting.
    • 100% on the test set is more often a sign of data leakage than of a brilliant model.
    • "Good enough" depends on the problem. 90% might be great for recommending movies and not enough for a medical test. Compare against a simple baseline (for example "always predict the most common class") and against how well humans do.
    Takeaway: Underfitting (high bias) = too simple: bad on train and test. Overfitting (high variance) = memorised: great on train, poor on test. Aim for a generalised model: good and similar scores on data it has never seen, not 100%.

    ⑦ Is there a standard industry cheat sheet?

    There isn't one official version. Good datasets come with documentation that answers these questions: dataset cards on Hugging Face, the data description tab on Kaggle, and the well-known "Datasheets for Datasets" question list. If a dataset has no documentation at all, treat that as a red flag.

    13. Common questions and quiz

    Questions learners usually ask

    Is data science the same as AI?
    No. They overlap through machine learning. Data science is about getting insights from data (including dashboards and statistics that aren't AI). AI is about making machines act smart (including rule-based systems that don't learn from data).
    Why so many names for the same thing (feature, independent variable, predictor…)?
    They come from different fields: statistics says "independent / dependent variable", ML says "feature / label", databases say "column / record". They mean the same thing.
    Is "predicting a number" always regression?
    Only if the number is an amount. If it's really a code or a name (PIN code, product ID), it's classification.
    If there are no labels, how does the machine know it's right?
    It doesn't, in the same way. We check that the groups are tight and well separated, and, most importantly, that people who know the business find them meaningful and useful.
    How many clusters should we ask for?
    There's no single right answer. Try a few numbers, look at how well separated the groups are, and pick the number that is clear and useful for the business.
    Why do people always use 42 as the seed?
    It's a joke from the book The Hitchhiker's Guide to the Galaxy. Any number works; the point is to use the same one so results can be reproduced.
    Is a high training score good news?
    Only if the validation/test score is also high and close to it. A high training score with a much lower test score is overfitting.
    Why not use 100% of the data for training?
    Then we'd have nothing unseen to check with, and couldn't tell learning apart from memorising.
    Do we use a validation set in classic machine learning?
    Yes: to compare models and pick settings, often through cross-validation. Deep learning also checks it after every epoch to decide when to stop.
    Can I use any data I find online?
    No. Check the licence, the site's terms and privacy laws. Personal data needs special care and consent.
